{# Seller Home — Skills page dialogs ===================================================================== Two SLDS 2 modal shells that back the overflow-menu actions on /skills.html: 1. `#skills-placeholder-modal` Reusable "not-yet-built" dialog for the Edit / Schedule / Share actions. Body copy is set from JS at open time so ONE modal serves all three actions — no per-action markup churn when a real editor / scheduler / share sheet lands. 2. `#skills-delete-modal` Destructive-confirm dialog for the Delete action. Copy is fixed per spec ("Delete this skill?" / "This removes the skill from your Skills page. This action can't be undone."). The primary action is styled destructive; secondary is neutral. Focus starts on the secondary button (Cancel) so a stray Enter press doesn't destroy anything. Both modals share: • `.slds-modal` + `.slds-modal__container` + `.slds-modal__header` + `.slds-modal__content` + `.slds-modal__footer` shell (same pattern _rename_source_modal.html uses). • `aria-modal="true"`, `role="dialog"`, `tabindex="-1"` so the dialog itself is the initial focus target when JS opens it. • A `.slds-backdrop` sibling that JS toggles in lock-step with `.slds-fade-in-open` on the modal. • `data-sh-skills-dialog-close` on every dismiss control (X, Cancel) so home.js can bind ONE delegated click handler. The dialogs are rendered as siblings of `.seller-home` so their `position: fixed` frame is anchored to the viewport, not to any scrolling parent inside the page shell. #} {# ── Placeholder dialog (Edit / Schedule / Share) ───────────────── Title + body text are `data-sh-skills-placeholder-*` targets; home.js writes them at open time from an in-JS lookup table. The dialog stays a single node so the "which action opened this" detail lives in JS, not in duplicated markup. #}

{# ── Leave-without-saving dialog (Schedule / navigate-away flow) ─── Opened by skill_detail.js when a Schedule click (or any other affordance that would navigate away from the detail page) fires while the editor is dirty. Three-button prompt per the Schedule spec — copy is fixed here so the dialog stays a single node: Title: "Leave without saving?" Body: "You have unsaved changes to this skill." Actions: Save and leave (primary, brand) Discard changes (destructive) Keep editing (secondary, neutral) Focus starts on "Keep editing" so a stray Enter press preserves the draft — same safety pattern as the Discard and Delete dialogs.
