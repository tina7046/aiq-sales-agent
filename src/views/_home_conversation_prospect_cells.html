{# Conversation prospect table — cell macros ===================================================================== One macro per column of the rich prospect table rendered inside an agent response (see `prospectTable` in _home_conversation_messages.html, which dispatches on `col.id`). Where this came from, twice over. The original was a port of the Approval Required table in the hunter prototype (`src/views/_prospect_list/_macros.html`), so density, avatars and badge treatment match the Prospecting surface a seller sees elsewhere. The current version came back from /prospect_table_lab.html, the sandbox copy of this file, after the layout was worked out there against the real account data. The lab is still the place to try the next change: it renders the same rows at the same 800 px width with its own stylesheet, so nothing there can affect the demo. That's also why the cell classes are spelled `ptl-` here. They were the lab's, and keeping the names means the next port is a copy of the changed block rather than a translation of it. Read the prefix as "prospect table", not "lab" — home_conversation.scss defines them scoped INSIDE the table wrapper, so they can't leak onto other pages. Same reasoning for the hunter-spelled utilities (`slds-td-formatter`, `cell_text_link`, the `*-fill-color` helpers). Differences from hunter, all deliberate: • No row-number gutter, no select-all checkbox column, no sort controls, no column-resize handles. The conversation table is a read-and-decide surface, not a list view to be managed. • No inline feedback column. Feedback on a specific draft belongs to the cadence card below the table, which has a per-prospect feedback field. • No `Review` button. In hunter it opens a side panel; this page has no side panel — the cadence card below the table plays that role. • One decision control, not two. Accept is gone and the X lives in the Prospect cell (see `decideButtons`), which makes the list read as opt-OUT: every prospect is in unless the seller removes one. The explicit yes comes from the cadence card's batch approve, not from the row. Every macro takes the conversation's own row object (see data/index.json → conversations[id].messages[].table.rows). Those rows are generated from the account and prospect CSVs, and they carry more fields than this page renders — `_hidden` in _home_conversation_messages.html decides which columns appear, and the macros for the skipped ones are kept below so a column comes back without rebuilding anything. #} {# ── Missing values ─────────────────────────────────────────────── The CSVs don't carry everything this table has columns for, so absent fields arrive as the literal string "n/a".
