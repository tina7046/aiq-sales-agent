{# Conversation prospect table — cell macros ===================================================================== One macro per column of the rich prospect table rendered inside an agent response (see `prospectTable` in _home_conversation_messages.html, which dispatches on `col.id`). Ported from the Approval Required table in the hunter prototype (`src/views/_prospect_list/_macros.html`) so density, avatars, badge treatment, and the inline-edit affordance match the Prospecting surface a seller sees elsewhere in the app. Differences from hunter, all deliberate: • No row-number gutter, no select-all checkbox column, no sort controls, no column-resize handles. The conversation table is a read-and-decide surface, not a list view to be managed. • No inline feedback column. Feedback on a specific draft belongs to the outreach review below the table, which already has a per-prospect feedback field. • No `Review` button. In hunter it opens a side panel; this page has no side panel — the inline outreach-review component below the table plays that role. • No `More Options` chevrons next to Accept / Reject. They were decorative in hunter (tooltip only) and would read as broken here. Every macro takes the conversation's own row object (see data/index.json → conversations[id].messages[].table.rows), so field names follow this page's flat convention (`prospect`, `role`, `company`) rather than hunter's (`prospectName`, `prospectTitle`, `companyName`). Utility class names (`slds-td-formatter`, `cell_text_link`, the `*-fill-color` helpers) are kept as hunter spells them, and home_conversation.scss defines them scoped INSIDE the table wrapper. Keeping the names aligned makes a future re-sync a diff rather than a translation; scoping them keeps them from leaking onto other pages. #} {# ── Prospect ───────────────────────────────────────────────────── Avatar + name / title / email / phone.
