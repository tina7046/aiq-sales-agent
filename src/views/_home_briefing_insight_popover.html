{# Home — Daily Briefing insight popover (reusable macro) ===================================================================== Renders one insight popover anchored to a Daily Briefing sentence link (e.g. "3 at-risk deals"). The popover exposes deeper context about the topic and two footer actions. Design source: Figma frame 8818:259732 ("📝 Popover/Default") in HkxLNEwVoTjmTPQY2HbDja. Layout: ┌─────────────────────────────────────────┐ │▲ │ ← nub (top-left) ├─────────────────────────────────────────┤ │ ✕ │ ← body row: text + close │ • Name · detail │ │ • Name · detail │ ← items list │ • Name · detail │ ├─────────────────────────────────────────┤ ← 1 px divider │ Set up a workflow [Review]│ ← footer actions (right) └─────────────────────────────────────────┘ Reusability ----------- ONE macro, N popover instances. Bind by data: each entry in `briefing.popovers` in home.json ships a `topicId` that matches the trigger link's `data-sh-briefing-topic`. home.js's `briefingPopoverController` resolves the pair at boot, wires the aria attributes on the trigger, and manages open/close. Consumer contract (see home.json → briefing.popovers[]): • topicId — trigger id (data-sh-briefing-topic value) • ariaLabel — accessible name for role="dialog" • description — intro sentence above the list • items[] — { id, name, value?, detail? } - name — semibold prefix (deal / entity name) - value — optional muted metric ($, %, count) - detail — optional muted rest-of-line (reason / status) The macro joins present fields with " · " so raw data stays free of typographic dots. A row with only { name } renders as just the name; a row with { name, detail } renders "Name · detail". • primaryAction — { id, label } → brand button, rightmost • secondaryAction — { id, label } → text-link button, to its left Either action is optional; the macro renders only the ones present. Additional briefing links (quota, re_engaged_buyers, upcoming_meetings) get popovers by adding another entry to `briefing.popovers`; no macro or JS changes required. a11y ---- • role="dialog" + aria-label (from ariaLabel) • aria-modal="false" — the popover is a non-modal disclosure, not a full-screen dialog; page-level focus trap would be wrong for a hover-triggered surface. • `hidden` attribute is the source of truth for closed state; the JS controller flips it and mirrors the state onto the trigger's aria-expanded. • The close button carries a concrete `aria-label` derived from the popover's `ariaLabel` ("Close at-risk deals preview") so SR users hear which surface they're dismissing. • Every focusable inside — close, secondary action, primary action — is a real {# Footer — divider above (top border), right-aligned actions.
