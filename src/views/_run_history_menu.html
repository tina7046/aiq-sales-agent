{# Run History dropdown ===================================================================== Header control for a scheduled workflow whose every run appended into the same conversation. Over weeks that thread gets long, so this is how the seller moves between runs: the trigger reports the current run, and picking an older one scrolls the feed to where that run starts. ── The trigger ────────────────────────────────────────────────────── A standard SLDS picklist: the `slds-combobox_container > slds-combobox.slds-dropdown-trigger_click` shell with a `slds-input_faux slds-combobox__input` value box and a right chevron. That gives it the bordered, full-height input look — the reason it's this and not the short badge it used to be. It carries the current run's state dot on the left (`slds-input-has-icon_left-right`); the reference SLDS picklist has no left icon, but the dot is worth keeping so the resting control shows the run's status at a glance. It is NOT a text field — it's a `role="combobox"` box you click (or Enter / Space / Down) to open. Typing happens on the search input inside the popover, below. ── The popover ────────────────────────────────────────────────────── The panel, its search box, and its rows are the Seller Home composer's agent switcher (`seller-home__composer-menu-list`, `-item`, `-label`, `-check`, in home.scss), so the hover, row rhythm, dot alignment, border-radius and check all match the agent chooser. Shown and hidden with the `hidden` attribute — the contract the composer menus use, which is why the combobox keeps `slds-dropdown-trigger_click` (the rule that undoes SLDS' hiding is scoped to it). The search is the cadence Prospect lookup's behaviour (home_conversation_lookups.js): immediate `input` filter, case-insensitive substring, an active row tracked with `aria-activedescendant`, and a "No matches found" row. Rows filter by toggling `hidden`. ── Contract ───────────────────────────────────────────────────────── Callers set, before including: • runHistory — `{ label?, runs: [...] }`, runs NEWEST-FIRST. • runConversationId — the conversation id; scopes element ids. • runInitialHidden — true for every conversation but the active one; `switchRunHistory` flips it at boot. Per run: `period` (pre-formatted date span for weekly, weekday+date for daily), `label` (the exact timestamp, kept for the side panel and search), `status` (`running` | `completed` | `failed`), and — when the conversation is NOT template-expanded — a `messageId` to scroll to.
